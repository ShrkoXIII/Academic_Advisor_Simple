# تدقيق دلالات المدخلات الأكاديمية

تاريخ التدقيق: `2026-10-11`. هذا التغيير يصحح التحقق من مدخلات API دون إعادة تدريب أو تغيير عقود الميزات أو قواعد استبدال نتيجة الإعادة في المعدل.

## مقام المعدل وحدود الزمن

| حقل الجامعة | الدلالة المؤكدة | استخدام API |
|---|---|---|
| `START_TOTAL_IN_CREDITS` | الساعات المكتملة/الناجحة عند بداية الفصل | `start_total_in_credits` فقط؛ لا يستخدم مقامًا للمعدل |
| `TOTAL_REG_CREDITS` | الساعات المسجلة المحتسبة رسميًا للمعدل وفق استثناءات الجامعة | مصدر المقام و`prior_total_reg_credits` عندما يثبت توقيته |
| `START_AGPA_POINTS` | المعدل التراكمي عند بداية الفصل | `start_agpa_points` وفق العقد الحالي |
| `SEMESTER_REG_CREDITS` | الساعات المسجلة في الفصل المستهدف | حد اتساق للزيادة المحتسبة؛ لا يفترض أنه كله محتسب للمعدل |

يرفق PHP في `integration_context.total_reg_credits_source` شهادة دلالات الحقل الأصلي:

```json
{
  "source": "official_sis_gpa_ledger",
  "target_part": 20251,
  "as_of_part": 20243,
  "timing": "beginning_of_semester",
  "rules_reference": "university_approved_credit_accounting_rules"
}
```

يجب أن يطابق `target_part` الطلب، وأن يساوي `as_of_part` الفصل السابق الذي تحسبه `previous_academic_part()`. لا يحتاج هذا المسار إلى نسخة إضافية من `current_gpa_credits`. يقارن Adapter أي مكمل اختياري بالقيمة الرسمية ويرفض التعارض.

الحالة `timing="end_of_semester"` تتطلب `as_of_part` يساوي الفصل المستهدف، و`semester_complete=true` و`additive_credit_accounting=true` و`semester_gpa_counted_credits` موثقًا بالشهادة ومراجع قواعد الجامعة نفسها. عندها فقط يطرح Adapter الزيادة الرسمية المحتسبة من `TOTAL_REG_CREDITS`. يجب ألا تتجاوز الزيادة الساعات المسجلة للفصل أو المجموع التراكمي. إذا تطلبت الإعادات أو الاستثناءات محاسبة غير جمعيّة فلا يفعّل PHP شهادة `additive_credit_accounting`؛ يستخدم مصدر بداية فصل موثقًا أو مكملًا موثقًا بدل الاشتقاق.

الاختبار الاصطناعي ذو `TOTAL_REG_CREDITS=129` و`SEMESTER_REG_CREDITS=18` لا يسمح بطرح `18` لمجرد وجود الحقلين. شهادة زيادة رسمية `18` تعطي `111`، وشهادة زيادة `15` بعد استثناء `3` تعطي `114`. لا يختار البرنامج أي رقم منهما من تلقاء نفسه.

عندما يكون الرد الأصلي غير موثوق التوقيت، يبقى `student_values.current_gpa_credits={value,source,as_of_part}` مصدرًا اختياريًا، ويجب أن يصف الفصل السابق مباشرةً. مصدر `prior_total_reg_credits` للميزات يوثق مستقلاً عند عدم توفر شهادة الحقل الرسمي. تظهر `summary.gpa_credit_provenance` مصدر كل مسار (`php_attested_total_reg_credits_beginning` أو `php_attested_total_reg_credits_derived` أو `sourced_override` / `sourced_supplement`). لا تضيف الاستجابة اسم المصدر الخاص أو محتوى بيانات الطالب.

شهادة قواعد الجامعة وتثبيت البيانات مسؤولية PHP الموثق. Python يتحقق من اتساق الشهادة والتوقيت والأرقام؛ لا يثبت قواعد الاستثناءات من الرد وحده. غياب المصدر أو غموض التوقيت يؤدي إلى خطأ محدد قبل inference.

## اتساق التدريب والميزات

الكود الفعلي في `src/features/temporal_features.py::add_student_history_features()` ينسخ `student_status.total_reg_credits` مباشرةً إلى `prior_total_reg_credits`، ويحسب `prior_fail_credit_ratio = total_fail_credits / total_reg_credits`. التعليق في الدالة يصف `total_*` بأنها معلومات بداية الفصل، لكن تسمية العمود والتعليق لا يثبتان التوقيت الفعلي لكل سجل أصلي.

`src/data/clean_student_status.py::clean_student_status()` يحول القيم إلى أرقام دون طرح `semester_reg_credits`. فحوص الاتساق في `src/data/clean_outliers.py` تقارن المجاميع فقط. `src/recommendation/engine.py::resolve_current_gpa_credits()` يستخدم `current_gpa_credits` عند تقديمه، وإلا يستخدم `prior_total_reg_credits`. لم تتغير هذه الحسابات أو قوائم الميزات أو المودلات.

**PASS:** إعادة استخدام تعريف الميزة الحالي واختبار التطابق على سجل اصطناعي ذي مصدر بداية فصل مثبت؛ المقام الرسمي يذهب إلى حقل الميزة الحالي دون تغيير التعريف. اختبارات الإعادات تبقي تطبيع الحالة وقواعد التوصية منفصلة عن تصحيح المقام.

**PARTIAL:** لم يقدم هذا التغيير دليلًا جامعياً يثبت أن كل `total_reg_credits` المستخدم في التدريب التاريخي كان من بداية الفصل. يلزم تدقيق منشأ ومواقيت جداول التدريب الأصلية مع الجامعة قبل إعلان الاتساق الدلالي الفعلي في الإنتاج. لم تُقرأ سجلات شخصية في الاختبارات، ولم تُعدّل أو تُعاد بناء الميزات التاريخية لإخفاء هذا الاعتماد.

## المحاولات والحالة السابقة

- `ATTEMPTS_COUNT=0` مع `FINISH_STATUS=null` يعطي `NEW` دون مكمل.
- `ATTEMPTS_COUNT>0` مع رمز رسمي معروف يستخدم `normalize_previous_status(..., official=True)`؛ `F/FE/FA` تعطي `FAILED` و`W` تعطي `WITHDRAWN`.
- الإعادة دون حالة تتطلب `previous_course_statuses` موثقًا؛ العدد وحده لا يعني رسوبًا أو انسحابًا.
- صفر محاولات مع نتيجة سابقة غير فارغة، أو فصل تسجيل سابق، أو مكمل حالة متعارض يرفض. الإعادة مع مكمل `NEW` ترفض.
- `LAST_REGISTER_SEMESTER_ID` إن توفر يجب أن يسبق الهدف. عدم وجوده لا يلغي الحالة الرسمية السابقة المؤكدة في رد المواد.
- تبقى `attempt_number = ATTEMPTS_COUNT + 1` كما كانت. لا يعاد تفسير `allowRegisterAllOptional` أو شروط الأهلية والقيود الحالية.
