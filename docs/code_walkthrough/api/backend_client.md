# الجلب المباشر الاختياري للاختبار

```text
src/api/backend_client.py
```

هذه الصفحة تصف الشفرة الموجودة في النسخة المفحوصة. الشفرة لم تُشغّل لتوليد توصية أو تدريب أثناء إعداد الشرح.

[العودة إلى مسار التعلم](../00_START_HERE.md)

## ١. لماذا يوجد هذا الملف؟

يوفر اتصالًا صغيرًا معزولًا للاختبار المحلي عندما لا تستخدم الخلفية الوسيطة الدفع. لا يغير عقد التوصية ولا يشغّل المحرك.

الدور في الخريطة:
واجهة وتشغيل

تصنيف الاستعمال:
نشط في مسار خدمة أو بناء أو تقييم أو أداة موثقة

## ٢. أين يقع في النظام؟

ما قبل هذه الوحدة يُعرف من الاستدعاءات والاستيرادات المباشرة؛ الاستيراد وحده لا يثبت تنفيذًا في كل طلب.

لم يظهر مستورد داخلي مباشر ضمن جرد الوحدات؛ لا يكفي ذلك للحكم أنه غير مستعمل.

الوحدات التي يعتمد عليها بعد ذلك:

- [أدوات الهوية والأرقام والتشخيص الآمن](validation.md)

## ٣. المدخلات

إعداد موثوق وهوية الطالب والاختصاص والفصل فقط. أسماء معاملات الطالب مثبتة في العقد الحالي، ومعاملات المواد من خريطة مشغّل الخدمة.

تواقيع الجدول أدناه مأخوذة من تعريفات الملف. نوع أو دلالة حقل لا يظهر في التوقيع يُفسر من الحسابات وشروط التحقق، ولا يفترض من الاسم وحده.

الأنواع والبنى المستعملة في هذا الحد:

```text
settings: ApiSettings
student_id: identity value
degree_id: identity value
part_id: academic part
```

## ٤. المخرجات

غلاف يحتوي الردين وسياقي جلب مستقلين. الفشل يعطي رمزًا آمنًا ولا يعيد العنوان أو الرمز السري أو جسم الجامعة.

مخرجات كل تابع التي تعاد صراحةً تظهر في جدول التعريفات. التعبير المعروض مقتطف من مسار إرجاع فعلي؛ ليس بديلًا عن شروط الوصول إليه.

أنواع المخرجات الأساسية:

```text
fetch_inputs(...) -> dict
_get(...) -> dict
```

### تسلسل المنطق وأسباب الخطوات

خطوة 1:

```text
BackendClient.fetch_inputs
```

يرفض الجلب المعطل؛ يطبع الهوية ثم يجلب الطالب والمواد تباعًا.

خطوة 2:

```text
BackendClient._address
```

يراجع جميع عناوين تحليل الاسم، لا العنوان الأول فقط، ويمنع الشبكات الخاصة إلا الحلقة المحلية المصرح بها.

خطوة 3:

```text
_PinnedHTTPSConnection.connect
```

يتصل بالعنوان الذي فُحص مع الاحتفاظ باسم المضيف للتحقق المشفّر؛ يمنع فجوة إعادة تحليل الاسم.

خطوة 4:

```text
BackendClient._exchange
```

يبعث طلب قراءة، يحد الجسم بثمانية ميبيبايت ويغلق الاتصال دائمًا.

خطوة 5:

```text
BackendClient._get
```

يرفض أي تحويل وجهة أو حالة غير ناجحة، ثم يحلل جسمًا قاموسيًا بأعداد عشرية.

## ٦. كيف تتغير البيانات؟

عنوان يحلل إلى عنوان عام وآخر خاص يُرفض كله. الرد المحول لا يُتبع.

## ٧. القواعد والافتراضات

لا متابعة لتحويلات الوجهة ولا استعمال تلقائي لوكلاء البيئة. المهلة موجبة ومحدودة رياضيًا؛ ليست وعدًا لأداء الإنتاج.

- القواعد الأكاديمية المؤكدة يُصرح بها عند توفر مصدرها؛ وجود شرط في الكود لا يمنحه اعتمادًا جامعيًا جديدًا.
- السياسات القابلة للإعداد والمصادر الخارجية يجب قراءتها مع صفحة الخدمة أو التدريب بحسب المسار.
- الدقة العددية والتفرد وترتيب الفصول افتراضات تقنية يفحصها الملف أو حدوده المجاورة.

## ٨. مخاطر التسرب والصحة

فحص الاسم ثم الاتصال باسم يعاد تحليله يسمح بتغير العنوان؛ التثبيت هنا يحفظ العنوان المفحوص. الرد الخام قد يحتوي بيانات شخصية فلا يُطبع.

لم يجر تعديل سلوك هذا الملف. المخاطر المذكورة حدود تفسير واستخدام وليست إعلانًا عن عطل جديد.

## ١١. القيود المعروفة

لا نقطة مواد أو معاملات مخترعة؛ نجاح الاختبارات الاصطناعية لا يثبت ربط الجامعة.

العلاقات المستخرجة من الاستيراد لا تثبت حركة طلب حي. تم تمييز مسار الخدمة والبناء والتقييم والتجربة من المستدعين ونقاط التنفيذ، لا من وجود الملف فقط.

## ١٢. مراجعة سريعة

ثلاث خلاصات:

- مسؤولية الملف: يوفر اتصالًا صغيرًا معزولًا للاختبار المحلي عندما لا تستخدم الخلفية الوسيطة الدفع. لا يغير عقد التوصية ولا يشغّل المحرك.
- مدخله ومخرجه مرتبطان بالدور المبين؛ لا تستعمله بدل طبقة التحقق المجاورة.
- أهم حد عملي: لا نقطة مواد أو معاملات مخترعة؛ نجاح الاختبارات الاصطناعية لا يثبت ربط الجامعة.

ثلاثة أسئلة للفهم:

1. ما الدليل المطلوب لصحة المدخل قبل استعمال هذا الملف؟
2. أي وحدة تستهلك المخرج، وما الذي يجب أن يظل ثابتًا عند انتقاله؟
3. أين يحدث الرفض أو الفقدان، وما الفرق بينهما في هذا المسار؟

تمرين قراءة آمن:

تتبع على الورق مدخلًا صغيرًا إلى المخرج عبر التسلسل أعلاه، وافتح تعريفًا واحدًا واختبارًا مرتبطًا لتحديد شرط رفضه. لا تنفذ نقطة تدريب أو توصية ولا تحفظ أو تفعّل تاريخًا.
