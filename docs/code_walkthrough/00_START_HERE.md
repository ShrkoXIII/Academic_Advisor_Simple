## ماذا يفعل المشروع؟

يستقبل حالة بداية فصل طالب ومواد تسمح الجامعة بتسجيلها. يثبت هويات المصادر وحدودها الزمنية، ويجهز ميزات الطالب والمادة من الماضي، ثم يولد خططًا تحقق الساعات والقيود ويرتب أفضل نتائج داخل قائمة مختصرة.

المخرجات تقديرات علامة ونقاط واحتمال رسوب ومعدل خطة وتراكمي متوقع، وليست ضمان نجاح أو إذنًا جديدًا لتسجيل مادة.

تتولى الخلفية الجامعية توثيق المستخدم والصلاحيات وجلب الردين. طبقة بايثون تتحقق من الاتساق وهوية الخدمة ومن مصادر الميزات والقيود، ثم تطبق المحرك.

```text
PHP-push -> FastAPI -> adapters -> ApiService -> TwoStagePlanRecommender
```

الجلب المباشر من بايثون مسار اختياري للاختبار المحلي، معطل افتراضيًا. لا تستدعيه نقطة التوصية المعتادة.

[شرح عميل الاختبار](api/backend_client.md)

## المعمارية في ست أفكار

١. **هوية قبل الحساب.** هوية الطالب والاختصاص والفصل تربط الطلب بكل سياق جلب على حدة. المحتوى الذي يحمل هوية يُفحص أيضًا. رد مواد بلا هوية داخلية يظل مربوطًا بشهادة الخلفية، لا بإثبات بايثون من المحتوى.

٢. **لقطة بداية الهدف.** نتائج فصل الهدف والمستقبل لا تدخل المعدلات السابقة. ساعات النجاح السابقة تختلف عن ساعات التسجيل المحتسبة في المعدل. مقام التراكمي يحتاج مصدرًا رسميًا ووقتًا مثبتًا.

٣. **تاريخ نهائي واحد.** كل طلب يستخدم نسخة واحدة من إحصاءات المواد حتى قطع أصغر من الهدف. التشغيل المعتاد يحتاج الفصل السابق بالضبط؛ الاختبار التاريخي يحتاج وضعًا وإعدادًا صريحين.

٤. **توقع ثم بحث ثم إعادة توقع.** الأولى تتوقع كل مادة بميزات لا تتعلق بخطة بعينها. البحث يولد جميع العضويات الممكنة ويرتبها إلى خمسين على الأكثر. الثانية تعيد التوقع مع سياق عضوية المادة في كل خطة مختصرة.

```text
Stage 1: 33 features
Stage 2: 47 features
Shortlist: <= 50
top_k: 3 by default
```

٥. **صلاحية الخطة مستقلة عن ترتيبها.** الساعات الدقيقة والسقوف والإعادات والمجموعات تقرر إمكان الخطة. التوازن هدف ناعم داخل الترتيب، لا حصة تسجيل إلزامية.

٦. **اعتماد واضح وحدود باقية.** بيان الأصول الحالي يعتمد استراتيجية جبهات المفاضلة في المرحلتين بنسختهما الأولى. هذا اعتماد اختيار ترتيب، وليس اعتماد أداء الإنتاج أو تحققًا تشغيليًا من ردود الجامعة.

```text
pareto v1 -> pareto v1
APPROVED
backend_max_candidate_count = UNRESOLVED
recommendation_latency_sla = UNRESOLVED
memory_budget_per_request = UNRESOLVED
```

## التدريب مختلف عن الاستدلال

التدريب يقرأ نتائج تاريخية ويجهز ميزات ويختار معاملات عبر طيات زمنية ويكتب مودلات ومستويات فئات. الاستدلال يقرأ هذه الأصول المتحققة ولا يلائمها أو يعيد اختيارها.

تحديث تاريخ الخدمة ليس تدريبًا؛ يضيف مجاميع فصل نهائي إلى نسخة ثابتة ويحفظ سلسلة مصدر. لا يغير أوزان المودل أو عقد ميزاته.

## ما الذي لم يُفترض؟

لم تُشغّل الخدمة على طالب حقيقي، ولم يُختبر الاتصال الخارجي أو تُهيأ نسخة تراكمية. الجذر التراكمي غير موجود في الحالة المحلية المفحوصة؛ آليته موجودة في الكود. الحزم السابقة موجودة، والاعتماد موجود في البيان، وحدود الأداء الجامعي وتوقيت مقام تصدير التدريب وقواعد استبدال الإعادة ليست محسومة من هذه المهمة.

بعض الوثائق السابقة تتحدث عن طبقة واجهات مستقبلية أو حد إصدارات قديم. صفحات هذا الدليل تعتمد الكود الحالي وتحيل إلى الوثائق السابقة دون إعادة كتابتها.
