# مراجعة خصائص المودل — 2026-09-10

تم إصلاح حسابات الخصائص وإعادة بناء ملفات features. إصدار الحسابات الحالي
`feature_engineering_version = 2`. النماذج ونتائج التقييم القديمة لم تُعدَّل؛
تحتاج إعادة تدريب وتقييم، ولا يجوز استخدام أرقامها لإثبات دقة النسخة المصححة.

## ما تغيّر

| الحساب | التصحيح |
|---|---|
| `prior_total_reg_courses/credits` | نسخ `total_reg_*` مباشرة؛ المصدر يمثل بداية الفصل |
| `prior_total_fail_courses/credits` | نسخ `total_fail_*` مباشرة دون طرح رسوب الفصل الحالي |
| `prior_fail_credit_ratio` | ساعات الرسوب السابقة ÷ ساعات التسجيل السابقة؛ المقام صفر يبقى مجهولًا |
| `prior_registered_semesters` | أخذ عداد التسجيل من الحالة السابقة في الاختصاص نفسه؛ العداد الحالي قد يتأثر بنتائج الفصل. الطالب بلا تاريخ تسجيل يبدأ بصفر، والتاريخ السابق غير المرصود يبقى مفقودًا |
| `gpa_prev_1/2` و`gpa_trend_*` | الحساب من سجل الحالات الكامل قبل التصفية بمفاتيح المواد، وتجاوز الفصول غير المسجلة باستخدام `semester_reg_courses > 0` |
| fallback أول معدل سابق | يعتمد على إجماليات بداية الفصل، وليس عداد `reg_total_semesters` الحالي |
| تاريخ المقرر المحفوظ | حفظ آخر فصل مستخدم ورفض تطبيق الحالة على الفصل نفسه أو فصل أقدم |
| تاريخ الاختصاص المجمد | رفض تداخل فصول الاختبار مع تاريخ التدريب |
| نتائج التجارب المحفوظة | إعادة الاستخدام مشروطة ببصمة بيانات features وكود التجارب وعقد الخصائص وإعدادات baseline وسلم العلامات |

ملف `build_temporal_features.py` يقرأ الحالات الخام وينظفها في الذاكرة دون
تطبيق course-key semi-join، ثم يربط الخصائص الناتجة بمفاتيح صفوف الأهداف نفسها.
لم تتغير سياسة اختيار صفوف الأهداف أو استبعاد `Z/D` أو تسجيلات `R/E`.

## بقية الحسابات التي روجعت

- صعوبة المقرر: متوسط العلامة والرسوب والمحاولات والإعادة والدعم وبدائل نقص
  التاريخ تستخدم نتائج الفصول السابقة. التحديث يأتي بعد استخراج خصائص الفصل.
- صعوبة الاختصاص والمتطلب: المجاميع الزمنية تستبعد الفصل الحالي. تاريخ اختبار
  2025 مجمد بعد تدريب 2024.
- `plan_*`: تجميع ساعات التسجيل وصعوبة المواد التاريخية؛ `peer_*` يستبعد المادة
  المستهدفة من البسط والمقام ومن أعلى خطر بين المواد المرافقة.
- GPA الطالب في 20252 يستطيع استخدام نتيجة 20251 السابقة؛ هذا تقييم عند بداية
  كل فصل، وليس توقع السنة كاملة مرة واحدة.
- `attempt_number` مبني على ترتيب المحاولات زمنيًا. البيانات الحالية لا تحتوي
  تكرارًا لنفس الطالب والمادة والفصل.
- الخصائص الثابتة مثل بيانات الشهادة والساعات وخصائص الخطة، و`part_semester`،
  لا تستخدم نتائج الفصل في حساباتها. سياسات تنظيف المصدر السابقة بقيت كما هي.
- مستويات categorical تتعلم من جزء fit فقط داخل كل validation fold؛ أوزان
  السنة والساعات تطبق على fit، ولا تدخل أهداف التقييم في اختيار الخصائص.
- أعمدة النتائج وملخصات نهاية الفصل مستبعدة من عقد المودل؛ أضيف عداد التسجيل
  الحالي `reg_total_semesters` إلى قائمة الأعمدة الممنوعة.

## التحقق

| الملف | صفوف المواد | حالات طالب/اختصاص/فصل | قيم سالبة ضمن `prior_*` بعد الإصلاح |
|---|---:|---:|---:|
| `temporal_train_features.parquet` | 365,585 | 77,362 | 0 |
| `temporal_test_features.parquet` | 68,578 | 12,976 | 0 |

مفاتيح المواد وترتيبها مطابقان لما قبل الإصلاح. كل إجماليات `prior_total_*`
تطابق إجماليات بداية الفصل في المصدر، ولا توجد قيم لا نهائية في مدخلات المودل.
حد تاريخ المقرر المحفوظ هو `20243`.

اختبار المسار الكامل يغيّر العلامات والنقاط وGPA والرسوب وعداد التسجيل في
الفصل الحالي والفصول اللاحقة، ثم يقارن جميع الخصائص الأساسية الـ47 وخصائص
الاختصاص الـ10. لا تتغير خصائص الفصل الحالي أو الفصول السابقة. توجد اختبارات
إضافية للحساب اليدوي للساعات وleave-one-out، وحفظ حد التاريخ، ورفض النتائج
المحفوظة غير المطابقة، وحفظ إصدار features داخل Parquet.

نجحت الاختبارات الـ25 كلها. وعلى البيانات الفعلية، تغيير نتائج 20251 وما بعده
لم يغيّر خصائص تاريخ الطالب في 400,507 صفوف تخص التدريب و20251. تحقق أيضًا
رفض metadata المودل القديم وتجاهل cache التجارب السابق.

نطاق هذا التحقق هو هندسة الخصائص على صفوف temporal الحالية؛ لم يُعِد تصميم
سياسات تنظيف البيانات واختيار العينة، ولم يُعِد تدريب النماذج.

## تشغيل المرحلة التالية

بعد مراجعة الإصلاح، ترتيب إعادة الإنتاج هو:

```powershell
python src/train_models.py
python src/evaluate_plan_gpa.py
python src/experiment_degree_points.py
python src/analyze_model_errors.py
```

يلزم تشغيلها ببيئة تحتوي LightGBM وscikit-learn. الـfeatures أعيد بناؤها بالفعل.
التقييم والترشيح يرفضان metadata النماذج القديمة، والتجربة تشترط baseline
وتقييمًا بالإصدار الجديد. قراءة ملفات تقييم قديمة مباشرة عبر pandas لا تعيد
تقييمها؛ تبقى تلك الملفات نتائج النسخة السابقة حتى إعادة تشغيل المسار أعلاه.
