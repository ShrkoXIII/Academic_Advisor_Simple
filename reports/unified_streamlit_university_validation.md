# منصة التحقق الأكاديمي والعرض الجامعي الموحدة

## النتيجة ونطاق العمل

أضيف وضع `🏛️ University Validation` إلى تطبيق Streamlit الموجود، مع ستة أقسام مترابطة. لم ينشأ موقع أو خادم جديد. بقيت أوضاع Production FastAPI وPilot وSearch Benchmark متاحة، وبقي أمر التشغيل نفسه. جميع المشاهد الجديدة تقرأ نتائج محفوظة؛ لا يؤدي تغيير الطالب أو الصفحة أو المودل أو الميزانية إلى استدلال.

الحالة النهائية بتاريخ 2026-10-25: **PASS** ضمن نطاق التطبيق المحلي والتحقق على النتائج المحفوظة. نجح 101 اختبار مركز و2011 اختبارًا في المجموعة الكاملة، وبقي 1614 ملفًا محميًا دون تغيير. تفاصيل الدليل أدناه.

الافتراضي التجريبي الجديد هو **SMART_SEARCH / 1000 / FULL_SPACE / B+C**. لا يغيّر ذلك Production أو نتائج FIRST_N القديمة، ولا يمثل اعتمادًا إنتاجيًا للخوارزمية. عند غياب التطابق يظهر `No saved results for this configuration` وزر تشغيل صريح. حدود الساعات من `credit_target.py`، والهدف يساوي الحد الأعلى الفعال بالضبط دون تخفيض تلقائي.

## التشغيل ودليل العرض المختصر

من جذر المستودع:

```powershell
.\.venv\Scripts\python.exe -m streamlit run .\tools\academic_advisor_streamlit\streamlit_app.py
```

لا يحتاج هذا الوضع خادم Pilot منفصلًا. Production يحتفظ بمتطلب FastAPI الحالي. استخدم التطبيق محليًا أو ضمن بيئة داخلية مخولة؛ لم ينفذ هذا العمل نشرًا عامًا أو يضف مصادقة لنشر عام.

1. اختر `🏛️ University Validation` من وضع التشغيل.
2. اختر `after_backend_fix` والطالب `P20251-04-P04` مرة واحدة.
3. من المصادر المشتركة اختر التاريخي `run_20261024T095941_95ed021f89`، وللتوصيات `benchmark_20261024T120117_4a7c2fc8`.
4. افتح `🎓 Student Validation`: اعرض المواد الفعلية والساعات والعلامات وGPA المحسوب، ثم أخطاء B/C الموقعة والمطلقة والرسم المقارن.
5. افتح `📚 Recommended Plans`: الإعداد SMART_SEARCH/1000/FULL_SPACE؛ استعرض Top 3 لكل مودل، وافتح تفاصيل المواد ودعم التاريخ/الأقران حيث هو محفوظ.
6. استخدم «الاختلافات فقط» لبيان البدائل والاستبدالات، ثم قارن B Top 1 وC Top 1 أو أي زوج من الخطط. التقاطع مع التسجيل الفعلي وصفي فقط.
7. اضغط `🔍 Compare Search Algorithms` أو انتقل إلى `🔎 Search Algorithms`، ثم بدّل المودل والميزانية 200/1000/2000. اعرض فروق المواد وregret وRecall، وخطط Oracle المكتملة.
8. افتح `📈 Cohort Evaluation` لعرض التقييم التاريخي للثلاثين ومقامات المؤشرات، ثم تنزيل CSVs. لا تخلط هذه العينة بمجموعة benchmark الخمسة.
9. افتح `🏛️ University Presentation`: الترتيب هو قبل التسجيل، الفعلي، تنبؤات الخطة الفعلية، البدائل، تحقق البحث، ثم القيود العلمية.
10. اختم بحدود الدليل: لا نعرف نتائج الخطط غير المختارة، ولا يثبت أعلى GPA متوقع تحسنًا فعليًا أو صلاحية تسجيل رسمية.

للبيانات غير المتوفرة: `P20251-01-P01` لديه نتائج تاريخية دون Oracle؛ اختر مصدره التاريخي وفعّل «عرض التشغيل التاريخي بإعداداته الأصلية صراحةً» لعرض FIRST_N/2000. `P20251-04-P01` توصيته محجوبة، لكن توقعات خطته الفعلية محفوظة وتظهر مستقلة.

## مقارنة البحث ومجموعات المواد

الميزانية الافتراضية للمقارنة 1000، ويمكن تغييرها إلى 200 أو2000، والنطاق FULL_SPACE أوFIXED_POOL. تُعرض صفوف الطرق الثلاث مع مصدر التشغيل، ثم Oracle المتوافق فقط. عند عدم حفظ إعداد إحدى الطرق يظهر UNAVAILABLE ولا تستبدل نتيجة طريقة أخرى به.

تُقارن Top 1 للطرق الثلاث بمصفوفة مواد ومشترك وحصري واستبدالات وGPA ومخاطر وJaccard، مع Top 3 في التفاصيل. Oracle ذو scope=EXHAUSTIVE وbudget=None؛ لا يحمل ميزانية المستخدم المحدودة. الرتبة العالمية للخطط وعدد التعادلات يظهران عندما يسمح السجل المحفوظ بذلك. Recall الدقيق يقيس الهوية، وscore-equivalent recall يقيس GPA مع التعادل. لا تستنتج recall كاملًا من Top 3 المعروضة وحدها.

عدم وجود Oracle لدى الطالب يظهر `ORACLE_UNAVAILABLE`. يمكن تشغيل تجربة محدودة الموارد بزر واحد في هذا القسم. تشغيل Oracle نفسه متاح صراحةً في وضع Search Benchmark الموجود؛ لا يوجد تشغيل تلقائي للثلاثين. قراءة النتائج وتغيير الأقسام لا يجريان inference.

## مقارنة المودلين على الخطة نفسها

يتاح زر «تشغيل تقييم مشترك للمودلين وحفظه» عند وجود مصدر benchmark متوافق. يختار B Top 1 وC Top 1 من النتيجة المحفوظة، ثم يقيم كل مجموعة مواد بكلا المودلين باستخدام `prepare_context/score_chunk` الموجودين، مع إعادة بناء ميزات الخطة. يُزال تكرار المجموعات؛ الحد الأعلى مجموعتان وأربعة تقييمات خطة/مودل. لا تستخدم الخطة الفعلية أو نتائجها في الاختيار أو التوجيه.

تتحقق التجربة من snapshot/semester/sample/strategy/budget/scope/target ومن بصمات المدخلات والمرشحين والنماذج، وهوية canonical والساعات الدقيقة. تنفذ في worker مستقل محدود بوقت300s وذاكرة2048MiB وحجم8MiB، وتحفظ أسرة منفصلة تحت `experiments/after_backend_fix/university_validation/cross_model/`. تعرض التجارب المحفوظة المطابقة فقط للطالب والإعداد ومصدر التشغيل. الحفظ مشمول ببصمة نزاهة. لم تُنفذ تجربة استدلال إضافية حقيقية ضمن عملية التحقق؛ اختبر المسار بمدخلات اصطناعية، ويبقى تشغيله من الواجهة فعلًا صريحًا.

## الاختبارات وأدلة الواجهة

أعيد تشغيل الواجهة ببيانات محفوظة حقيقية للطلاب الثلاثة أعلاه في الأقسام الخمسة التفصيلية: **15 عرضًا دون خطأ**. مُنعت HTTP وطرق الاستدلال وبدء التجارب أثناء الفحص، وظلت `search.engine=None` وقوائم predictors/runners فارغة. الدليل `saved_data_apptest.json` يحتوي مؤشرات العرض ومصادره دون هويات أصلية. هذا دليل AppTest؛ لم يُنشأ موقع أو instance لتصوير متصفح مستقل.

## القيود العلمية والتشغيلية

- النتائج البديلة counterfactual؛ لا نملك درجاتها الفعلية. ارتفاع GPA المتوقع لا يثبت مودلًا أفضل أو خطة أفضل فعليًا.
- اكتمال exhaustive يثبت أمثلية حسابية وفق المودل والقيود المنفذة فقط؛ السياسات والأهلية الرسمية ما زالت جزئية التحقق.
- GPA الفصلي المحسوب ليس GPA رسميًا مؤكدًا؛ المعدل التراكمي الرسمي غير مدعوم دون مقام وسياسة إعادة موثقة.
- ما زالت بعض دلالات توقيت مدخلات API التاريخية غير مثبتة. لم يتغير هذا القيد بتجميل الواجهة.
- Smart/1000 افتراضي عرض تجريبي، وليس قرار ترقية Production. لا Oracle للبقية لمجرد توافره لدى خمسة.
- التجارب القديمة متعددة السيناريوهات أو مجهولة السياق لا تُدمج ضمنًا؛ تعرض أداة Pilot الحالية السيناريوهات الصريحة.
- القراءة تتضمن فحص hashes وملخصات/SQLite للنتائج؛ قد يطول الفتح الأول، لكنه لا يحمل مودلًا ولا ينفذ inference.
- الاستضافة العامة أو صلاحيات عرض بيانات الطالب تحتاج ضوابط نشر ومصادقة مستقلة؛ لم يُطلق خادم أو نشر في هذه المهمة.
